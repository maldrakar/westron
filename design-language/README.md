# Design language

The westron design language, in chapters `00` to `09` (issue #8). A chapter answers the question "why is it this way";
values live in `tokens/`, component rules in `spec/components/`.

| [01. Tone](01-tone.md) | The voice of interface copy and direction B's visual temperament | Draft for approval |
| [02. Color](02-color.md) | Cool neutrals, the cobalt accent, statuses, list colors, charts, the four themes, contrast | Draft for approval |
| [03. Typography](03-typography.md) | Onest headings, the system font for body text, Geist Mono for code, the seventeen text roles | Draft for approval |
| [04. Shape](04-shape.md) | Radius roles, strokes, two-layer shadows by theme | Draft for approval |
| [05. Motion](05-motion.md) | The eight motions, one spring model for every platform, Reduce Motion | Draft for approval |
| [06. Layout](06-layout.md) | The space ladder, direction B's rhythm, density, size by platform | Draft for approval |
| [07. Icons](07-icons.md) | Icon names, system icons and westron's domain set, status glyphs, size relative to text | Draft for approval |
| [08. Accessibility](08-accessibility.md) | Targets and how westron checks them | Draft for approval |
| [09. Platform adaptation](09-platform-adaptation.md) | What stays with the system and what westron controls (#9) | Draft for approval |
